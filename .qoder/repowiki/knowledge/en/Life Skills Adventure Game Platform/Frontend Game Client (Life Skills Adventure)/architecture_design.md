Single HTML entry (`index.html`) served as static assets from `backend/public/`, loading scripts in a fixed dependency order: global utilities first (`api.js`, `i18n.js`, `story-i18n.js`, `chat-agent.js`, `session-scoring.js`, `rewards.js`, `auth-ui.js`), then puzzle modules (`puzzle-types.js`, `puzzles.js`), then story engine (`story-adventure.js`), then the ES module `world3d.js` (Three.js loaded via an importmap from unpkg), and finally the orchestrator `game.js`. The app is a screen-based SPA: `#screen-auth`, `#screen-missions`, and `#screen-game` sections are toggled via `showScreen()` in `game.js`, which also owns the central `state` object (missions, progress, sessionId, scenario, gameState, clues, sessionXp). `api.js` exposes a singleton `window.api` (`GameAPI`) that abstracts all `/api/v1/*` calls and includes a built-in mock backend for local development / guest mode, so the frontend runs without a live server. `world3d.js` encapsulates the Three.js scene and is disposed when leaving the game screen; `story-adventure.js` drives the narrative/chat flow and exposes `StoryEngine`/`StoryI18n` globals consumed by `game.js` and `chat-agent.js`. CSS lives under `css/game.css`; no build step — plain ES5/ES6 scripts loaded via `<script>` tags.
