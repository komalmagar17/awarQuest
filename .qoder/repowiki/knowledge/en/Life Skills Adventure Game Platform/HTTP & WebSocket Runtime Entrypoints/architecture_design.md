Two-file runtime entrypoint pattern: `server.js` is the process root that connects to the database via `connectDatabase`, creates an `http.createServer` wrapping the Express `app` from `app.js`, attaches a Socket.IO server on top of it, calls `initializeSockets(io)` from `sockets/index.js`, then listens on `env.PORT`. `app.js` configures the Express instance (helmet, cors with origin allowlist, pino-http logging, cookie parsing, JSON body limiting, security middleware) and mounts versioned route modules under `/api/v1/*`, plus static assets and health endpoints (`/health`, `/health/ready`). The `sockets/index.js` module exposes only `initializeSockets`, which registers a single `connection` handler that joins sockets into `game_<id>` rooms via `socket.join`. Graceful shutdown in `server.js` closes Socket.IO, then the HTTP server, then the Sequelize connection, with a 10s forced timeout. Dependency direction is one-way: `server.js` → `app.js` + `sockets/index.js`; neither imports back into the other.
