The module is split into two sibling packages with a one-way dependency direction: `backend/config/` is consumed by `backend/utils/` only via `logger.js`, never the reverse. `config/env.js` is the single source of truth for runtime settings — it loads `.env` via `dotenv`, validates every key against a `joi` schema (including conditional requirements like `AI_SERVICE_TOKEN` depending on `AI_ENABLED`), and exports a normalized object with derived fields (`corsOrigins`, `isProduction`). `config/db.js` builds a singleton `Sequelize` instance using those env values, wires query logging through `pino`, enforces SSL based on `DB_SSL`, and exposes `connectDatabase()` which conditionally runs `sequelize.sync` and applies any top-level `migrations-*.sql` files when `AUTO_SYNC` is enabled (guarded against production). `config/logger.js` initializes a `pino` logger that switches to `pino-pretty` in non-production when available. `config/resource-catalogue.js` is a pure data module exporting static `INDIA_REGIONS` and `CURATED_RESOURCES` arrays used elsewhere in the app. `utils/` contains framework-agnostic helpers: `app-error.js` defines an `AppError` class carrying `statusCode`, `code`, and `isOperational`; `async-handler.js` wraps Express route handlers so async rejections are forwarded to `next`; `mission-order.js` provides a fixed priority list and a `sortMissions` comparator for deterministic ordering of mission slugs.
